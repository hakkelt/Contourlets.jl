API Reference

The transforms, their workspaces and the interface functions are exported. The pyramid and directional-filter-bank stages under Building blocks are public but not exported: import them by name, as in using Contourlets: lp_decompose.

Module

Contourlets.Contourlets — Module
Contourlets

Two-dimensional contourlet transforms, as transform objects of AbstractMultiscaleTransforms, whose interface this package re-exports.

x̂ = synthesize(t, c)

Default filters

  • CDF97 — CDF 9/7 biorthogonal filter pair for the Laplacian Pyramid stage.
  • Q2345 — Quincunx biorthogonal filter pair for the DFB stage.

Volumes

This package is planar throughout: the quincunx lattice, the shear index remap and the Q2345 ladder all rely on properties of the plane. Volumes are covered by Surfacelets.jl, which is a different construction rather than this one with an extra axis — its directional stage is an hourglass filter bank built from Bernstein mapping kernels, with no sampling matrix or ladder filter in it at all. The two packages share only the pyramid filter machinery, which lives in MultiscaleFilterBanks.jl; its filter types FilterPair and CDF97 are re-exported here.

Building blocks

The pyramid and directional stages (lp_*, nsp_*, qfb_*, dfb_*, nsdfb_*) and the filter utility upsample_kernel are public but not exported: load them by name, e.g. using Contourlets: lp_decompose, dfb_decompose.

Transforms

Contourlets.CT — Type
CT(; scales, direction_levels, lp_filters = CDF97, dfb_filters = Q2345)
CT{T}(; scales, direction_levels, lp_filters = CDF97, dfb_filters = Q2345)

The discrete contourlet transform of Do & Vetterli (2005): a Laplacian pyramid of scales levels whose bandpass image at scale j is split by a decimated directional filter bank of depth direction_levels[j]. It is nearly critically sampled (about 4/3 coefficients per pixel); its subbands have different sizes, so the coefficients are a SubbandVector.

Image sizes: any size whose bandpass at every scale suits that scale's directional filter bank. The bandpass at the finest scale has the image's size and each coarser one half of it, rounded up; a depth l ≥ 1 needs both of its sides divisible by 2^max(l - 1, 1) (depth 0 takes any size). For example CT(scales = 3, direction_levels = [0, 2, 3]) takes 100 × 100, and direction_levels = [0, 0] takes odd sizes. A size that does not fit throws an ArgumentError naming the scale, the axis and the nearest length that fits.

  • scales: the number of pyramid levels (≥ 1), J in the papers;
  • direction_levels: the depth of the directional filter bank at each scale, scales entries ≥ 0, coarsest scale first; scale j has 2^direction_levels[j] directions. These are the l_j of the papers and the nlevs of the MATLAB toolboxes;
  • lp_filters: the pyramid's biorthogonal filter pair (CDF97 by default);
  • dfb_filters: the ladder pair of the directional filter banks (Q2345 by default).

At least one of scales and direction_levels must be given: scales alone takes direction_levels = parabolic_levels(scales) (see parabolic_levels), direction_levels alone has scales = length(direction_levels), and when both are given they must agree. The filters are stored at the precision of the wider of the two pairs, or at precision T with the {T} form; a transform runs at the precision of its data (Float32 data uses Float32 filters), whatever the precision it holds. Transforms with equal parameters are == and hash alike.

The parameters are public properties: t.scales, t.direction_levels (a read-only vector), t.lp_filters and t.dfb_filters.

Subbands (subband_layout): the lowpass first, as (scale = 0, direction = 0), then for scale = 1 (the coarsest), 2, …, scales (the finest) its directional subbands (scale = j, direction = k), k = 1, …, 2^direction_levels[j]. The transform runs serially; threaded is accepted and ignored.

Examples

julia> using Contourlets, Random

julia> x = randn(Xoshiro(1), 64, 64);

julia> t = CT(scales = 2, direction_levels = [1, 2])
CT(scales = 2, direction_levels = [1, 2])

julia> c = analyze(t, x);

julia> nsubbands(t, size(x)), size(subband(t, c, 1))
(7, (16, 16))

julia> maximum(abs, synthesize(t, c) .- x) < 1e-12
true

Contourlets.NSCT — Type
NSCT(; scales, direction_levels, lp_filters = CDF97, dfb_filters = Q2345)
NSCT{T}(; scales, direction_levels, lp_filters = CDF97, dfb_filters = Q2345)

The nonsubsampled contourlet transform of da Cunha, Zhou & Do (2006): the contourlet transform without its samplers (a nonsubsampled pyramid and nonsubsampled directional filter banks), so every subband has the image's size and the transform commutes with circular shifts of the image. The coefficients are one array of size (size(x)..., n), subband i being c[:, :, i].

  • scales: the number of pyramid levels (≥ 1), J in the papers;
  • direction_levels: the depth of the directional filter bank at each scale, scales entries ≥ 0, coarsest scale first; scale j has 2^direction_levels[j] directions. These are the l_j of the papers and the nlevs of the MATLAB toolboxes;
  • lp_filters: the pyramid's biorthogonal filter pair (CDF97 by default);
  • dfb_filters: the ladder pair of the directional filter banks (Q2345 by default).

At least one of scales and direction_levels must be given: scales alone takes direction_levels = parabolic_levels(scales) (see parabolic_levels), direction_levels alone has scales = length(direction_levels), and when both are given they must agree. The filters are stored at the precision of the wider of the two pairs, or at precision T with the {T} form; a transform runs at the precision of its data (Float32 data uses Float32 filters), whatever the precision it holds. Transforms with equal parameters are == and hash alike.

The parameters are public properties: t.scales, t.direction_levels (a read-only vector), t.lp_filters and t.dfb_filters.

Subbands (subband_layout): the lowpass first, as (scale = 0, direction = 0), then for scale = 1 (the coarsest), 2, …, scales (the finest) its directional subbands (scale = j, direction = k), k = 1, …, 2^direction_levels[j].

With a workspace and threaded = true (the default threaded = nothing means true for complex data, false for real data) the independent subband FFTs of a host workspace run in one task per Julia thread, or in at most the tasks the workspace was built with (make_workspace).

julia> c = analyze(t, x);

(32, 32, 7)

julia> maximum(abs, synthesize(t, c) .- x) < 1e-12

Contourlets.TICT — Type
TICT(; scales, direction_levels, lp_filters = CDF97, dfb_filters = Q2345)
TICT{T}(; scales, direction_levels, lp_filters = CDF97, dfb_filters = Q2345)

The translation-invariant contourlet transform of Eslami & Radha (2006). A translation-invariant Laplacian pyramid of scales levels gives, at every level i, four full-size highpass channels; each is split by a translation-invariant directional filter bank of depth direction_levels[i]: the full tree for channels 1 and 4 (2^direction_levels[i] subbands), a half tree for channels 2 and 3 (2^(direction_levels[i] - 1) + 1 subbands). Every subband has the image's size, and the transform commutes with circular shifts of the image. The coefficients are one array of size (size(x)..., n), subband i being c[:, :, i].

The redundancy is 3 Σᵢ 2^direction_levels[i] + 2 scales + 1 when every direction_levels[i] ≥ 1 (a level with direction_levels[i] = 0 contributes its 4 channels). STICT trades the directional stage's translation invariance for a redundancy of 4 scales + 1. lp_filters must be biorthogonal (as CDF97 is).

  • scales: the number of pyramid levels (≥ 1), J in the papers;
  • direction_levels: the depth of the directional filter bank at each scale, scales entries ≥ 0, coarsest scale first; scale j has 2^direction_levels[j] directions. These are the l_j of the papers and the nlevs of the MATLAB toolboxes;
  • lp_filters: the pyramid's biorthogonal filter pair (CDF97 by default);
  • dfb_filters: the ladder pair of the directional filter banks (Q2345 by default).

At least one of scales and direction_levels must be given: scales alone takes direction_levels = parabolic_levels(scales) (see parabolic_levels), direction_levels alone has scales = length(direction_levels), and when both are given they must agree. The filters are stored at the precision of the wider of the two pairs, or at precision T with the {T} form; a transform runs at the precision of its data (Float32 data uses Float32 filters), whatever the precision it holds. Transforms with equal parameters are == and hash alike.

The parameters are public properties: t.scales, t.direction_levels (a read-only vector), t.lp_filters and t.dfb_filters.

Subbands (subband_layout): the lowpass first, as (level = 0, channel = 0, direction = 0), then for level = 1 (the coarsest), 2, …, scales (the finest), for channel = 1, …, 4, the directional subbands (level = i, channel = c, direction = k).

Threading as for NSCT.

Examples

julia> using Contourlets, Random

julia> x = randn(Xoshiro(1), 32, 32);

julia> t = TICT(scales = 2, direction_levels = [1, 2]);

julia> c = analyze(t, x);

julia> size(c, 3) == 1 + (2 + 2 + 2 + 2) + (4 + 3 + 3 + 4)
true

julia> maximum(abs, synthesize(t, c) .- x) < 1e-12
true

Contourlets.STICT — Type
STICT(; scales, direction_levels, lp_filters = CDF97, dfb_filters = Q2345)
STICT{T}(; scales, direction_levels, lp_filters = CDF97, dfb_filters = Q2345)

The semi-translation-invariant contourlet transform of Eslami & Radha (2006): the translation-invariant Laplacian pyramid of TICT followed by critically sampled directional filter banks (full tree on channels 1 and 4, half trees on 2 and 3). The pyramid commutes with circular shifts; the directional subbands are those of the decimated DFB. Redundancy 4 scales + 1; the subbands have different sizes, so the coefficients are a SubbandVector.

Both image dimensions must be divisible by 2^max(L - 1, 1) for the deepest directional level L.

  • scales: the number of pyramid levels (≥ 1), J in the papers;
  • direction_levels: the depth of the directional filter bank at each scale, scales entries ≥ 0, coarsest scale first; scale j has 2^direction_levels[j] directions. These are the l_j of the papers and the nlevs of the MATLAB toolboxes;
  • lp_filters: the pyramid's biorthogonal filter pair (CDF97 by default);
  • dfb_filters: the ladder pair of the directional filter banks (Q2345 by default).

At least one of scales and direction_levels must be given: scales alone takes direction_levels = parabolic_levels(scales) (see parabolic_levels), direction_levels alone has scales = length(direction_levels), and when both are given they must agree. The filters are stored at the precision of the wider of the two pairs, or at precision T with the {T} form; a transform runs at the precision of its data (Float32 data uses Float32 filters), whatever the precision it holds. Transforms with equal parameters are == and hash alike.

The parameters are public properties: t.scales, t.direction_levels (a read-only vector), t.lp_filters and t.dfb_filters.

Subbands (subband_layout) are ordered as for TICT. The transform runs serially; threaded is accepted and ignored.

Examples

julia> using Contourlets, Random

julia> x = randn(Xoshiro(1), 32, 32);

julia> t = STICT(scales = 2, direction_levels = [2, 3]);

julia> c = analyze(t, x);

julia> length(c) == 9 * length(x)
true

julia> maximum(abs, synthesize(t, c) .- x) < 1e-12
true

Contourlets.parabolic_levels — Function
parabolic_levels(scales, coarsest = 1) -> Vector{Int}

The directional depths of scales scales, coarsest first, following the parabolic scaling law

l_j = coarsest + ⌊(j - 1) / 2⌋,    j = 1, …, scales,

so that the number of directions doubles every other scale from the coarsest (l_1 = coarsest) to the finest (j = scales) — the discrete counterpart of parabolic scaling, width ∝ length², in Do & Vetterli (2005). It is the default direction_levels of the transforms built with scales alone.

Examples

julia> using Contourlets

julia> parabolic_levels(4)
4-element Vector{Int64}:
 1
 1
 2
 2

julia> parabolic_levels(5, 2)
5-element Vector{Int64}:
 2
 2
 3
 3
 4

Running a transform

These functions come from AbstractMultiscaleTransforms.jl; each entry gives the general contract first and the contourlet methods after it. Every function also accepts a workspace in place of the transform, as in analyze(ws, x) and synthesize!(x, ws, c).

AbstractMultiscaleTransforms.analyze — Function
analyze(t, x; workspace = nothing, threaded = nothing) -> c
analyze(ws, x; threaded = nothing) -> c

Analysis (forward) transform of the array x by the transform t. The coefficients c are an array: transforms whose subbands all have the size of x stack them into one array of size (size(x)..., n); critically sampled separable transforms may pack them as blocks of one array of the size of x; others return a SubbandVector or a package-specific array. Read subbands with subband; synthesize inverts the transform.

workspace is a workspace from make_workspace matching t and x; threaded = nothing leaves threading to the transform's documented default, true/false asks for or against threads (a transform that never threads ignores it).

analyze(f, t, x; workspace = nothing, threaded = nothing) -> nothing

Streaming form (only where supports_streaming(t)): calls f(i, band) once for every subband i instead of storing the coefficients. band is valid only until f returns.

Workspaces

AbstractMultiscaleTransforms.make_workspace — Function
make_workspace(t, T::Type{<:Number}, dims; kwargs...) -> AbstractTransformWorkspace
make_workspace(t, x::AbstractArray; kwargs...) -> AbstractTransformWorkspace

Precompute what transform t needs for data of element type T and size dims. The second form takes element type, size and array type (so the device) from x.

Every transform accepts these keywords on both forms, so that code can build a workspace without knowing the transform family. A transform with no use for one accepts and ignores it, and says so in its documentation; the defaults are the transform's own (its fastest choice).

  • flags: the FFTW planner flags of the host FFT plans (an integer, such as FFTW.MEASURE or FFTW.ESTIMATE).
  • tasks: the most tasks a call with the workspace runs on the host, and with them the per-task buffers; nothing means one per Julia thread, 1 a serial workspace.
  • tune: measure the fastest batching of a device workspace at construction (a Bool).
  • prewarm: run the transform once at construction, so that the first call is compiled and allocates nothing (a Bool).

A transform may accept further keywords of its own. An unknown keyword throws a MethodError.

Without a method for t, both return a DefaultWorkspace, which holds nothing but (t, T, dims) and ignores the keywords above.

source
make_workspace(t::Union{CT, NSCT, TICT, STICT}, T::Type{<:Number}, dims; flags = FFTW.MEASURE, tasks = nothing, tune = false, prewarm = true)
make_workspace(t::Union{CT, NSCT, TICT, STICT}, x::AbstractMatrix; kwargs...)

The workspace of the contourlet transform t (CTWorkspace, NSCTWorkspace, TICTWorkspace or STICTWorkspace) for images of size dims and element type T (real or complex; an integer type means float(T)), on the host. The second form takes size, element type and array type from the image x; pass a device array to build a device workspace. With it, analyze! and synthesize! allocate nothing. The workspace runs at the precision of T: a Float32 workspace converts the filters of a Float64 transform. A workspace's buffers serve one call at a time: tasks that run transforms concurrently need a workspace each.

Keywords, accepted by the workspaces of all four transforms (the shared keywords of make_workspace in AbstractMultiscaleTransforms):

  • flags = FFTW.MEASURE: the FFTW planner flags of the host FFT plans — those of the directional filter banks of a CT or STICT, and the image-size FFTs of an NSCT or TICT, which are planned single-threaded because the workspace threads over its subbands instead. FFTW.ESTIMATE builds the workspace faster, possibly with slower plans. Device plans ignore it.
  • tasks = nothing: the most tasks an NSCT or TICT host workspace splits its subband FFTs between, and so the number of its per-task FFT buffers; nothing means one per Julia thread, 1 a serial workspace whose calls run on the calling task whatever their threaded. It must be at least 1. The CT and STICT run serially and a device workspace runs one task, so there it is checked and otherwise ignored.
  • tune = false: for NSCT and TICT workspaces on a device, measure how many subbands each batched FFT should take, and whether the synthesis should be batched too (MultiscaleFilterBanks.mask_bank_tune); this runs a few transforms at construction. On an A100 (Float32, 256² and 512²) tuning adds 40–240 ms to the construction and makes the synthesis 1.6–2.6× and the TICT analysis 15–25% faster, so it pays off for a workspace that runs more than about 150 (NSCT) to 330 (TICT) analysis–synthesis pairs, as in an iterative reconstruction. Host workspaces thread over their subbands instead, and the CT and STICT have nothing to tune: there it is ignored.
  • prewarm = true: run one analysis and synthesis on zeros at construction, so that the first call is compiled and allocates nothing. The warm-up threads as a call with the default threaded = nothing does.

Examples

julia> using Contourlets

julia> t = CT(scales = 2, direction_levels = [1, 2]);

julia> ws = make_workspace(t, Float64, (64, 64));

julia> transform(ws) == t, eltype(ws), size(ws)
(true, Float64, (64, 64))

AbstractMultiscaleTransforms.SubbandVector — Type
SubbandVector(data::AbstractVector, layout::SubbandLayout)

Coefficients made of subbands of different sizes, stored one after another in the single vector data (a host Vector or a device vector) and presented as an AbstractVector of all coefficients. subband(c, i) is a reshaped view of subband i.

Broadcasting, similar, copyto!, fill!, ==, isapprox, mapreduce (sum, maximum, ...) and LinearAlgebra.dot/norm/axpy!/axpby!/ rmul!/lmul! act on data directly, so they need no scalar indexing on a device and keep the layout. Operands of one operation must share a layout. Adapt.adapt moves the storage (a method defined once Adapt is loaded, as every GPU array package does).

julia> using AbstractMultiscaleTransforms

julia> layout = SubbandLayout([(2, 2), (4, 4)], (4, 4));

julia> c = SubbandVector(collect(1.0:20.0), layout);

julia> subband(c, 1)
2×2 reshape(view(::Vector{Float64}, 1:4), 2, 2) with eltype Float64:
 1.0  3.0
 2.0  4.0

julia> d = 2 .* c .+ 1;

julia> d isa SubbandVector && subband(d, 1)[1] == 3.0
true

Filters

MultiscaleFilterBanks.CDF97 — Constant
CDF97 :: FilterPair{Float64}

The Cohen–Daubechies–Feauveau 9/7 biorthogonal filter pair [1], the irreversible wavelet filter of JPEG 2000 Part 1 [3], introduced for image coding by Antonini et al. [2]. The 9-tap analysis low-pass h is normalized to unit DC gain, the 7-tap synthesis low-pass g to DC gain 2, which compensates the ×2 upsampling of the Laplacian pyramid's synthesis step. Both are symmetric, centered at taps 5 and 4. Like every pair, it is read-only (ReadOnlyTaps).

julia> using MultiscaleFilterBanks: CDF97

julia> isapprox(sum(CDF97.h), 1.0; atol = 1e-12)
true

julia> isapprox(sum(CDF97.g), 2.0; atol = 1e-12)
true

References

  2. M. Antonini, M. Barlaud, P. Mathieu, and I. Daubechies, "Image Coding Using Wavelet Transform", IEEE Transactions on Image Processing, 1(2):205–220, 1992. doi:10.1109/83.136597
  3. ISO/IEC 15444-1, Information technology — JPEG 2000 image coding system: Core coding system.

Contourlets.Q2345 — Constant
Q2345 :: QuincunxFilterPair{Float64}

The "23-45" biorthogonal quincunx filter pair of Phoong et al. (1995) for the DFB stage, parameterized by the 12-tap ladder filter β of their Example 3.2 (stored in f_ladder). The directional filter banks use its 2-D quincunx mapping, whose analysis filters have 23 × 23 and 45 × 45 support. Perfect reconstruction is structural — exact to machine precision at every tree depth.

julia> using Contourlets, Random

julia> using Contourlets: qfb_decompose, qfb_reconstruct

julia> x = randn(Xoshiro(1), 16, 16);

julia> maximum(abs, qfb_reconstruct(qfb_decompose(x, Q2345)..., Q2345) .- x) < 1e-12
true

MultiscaleFilterBanks.FilterPair — Type
FilterPair(h::AbstractVector, g::AbstractVector)
FilterPair{T}(h, g)

A 1-D biorthogonal filter pair holding an analysis (h) and synthesis (g) low-pass filter vector. Both filters are stored as coefficient vectors whose center tap is at index ceil(Int, length/2) (1-based Julia indexing). T <: AbstractFloat is the element type, by default float of the promoted element types of h and g; the fields h and g are ReadOnlyTaps. Empty filters, and filters not indexed from 1, throw an ArgumentError.

Give odd, symmetric filters, so that the pyramid does not shift the image. By the convention of CDF97, h has DC gain 1 (its taps sum to 1) and g has DC gain 2, which compensates the ×2 upsampling of the decimated pyramid; nsp_atrous_filters halves g for the nonsubsampled one.

The pair drives the pyramid stage of the downstream transforms: h produces the coarse approximation, and g predicts the input from it, so that the difference is a bandpass (the Laplacian pyramid of Burt and Adelson [1]). Adding the prediction back reconstructs the input for any pair. Do and Vetterli [2] show that the pyramid is a frame, tight for orthogonal filters, and give a projection reconstruction that is more robust to noise than the usual one. Its nonsubsampled (à trous) form is the pyramid of the nonsubsampled contourlet transform [3].

Examples

julia> using MultiscaleFilterBanks: FilterPair

julia> spline = FilterPair([1, 2, 1] ./ 4, [1, 2, 1] ./ 2);   # linear spline pair

julia> sum(spline.h), sum(spline.g), eltype(spline)
(1.0, 2.0, Float64)

The pair copies the filters into ReadOnlyTaps vectors: it cannot be changed after it is built, and two pairs are == (and hash alike) when their taps are equal.

Contourlets.QuincunxFilterPair — Type
QuincunxFilterPair{T}
QuincunxFilterPair(f_ladder)
QuincunxFilterPair{T}(f_ladder)

A two-channel quincunx filter pair for the DFB stage: the quincunx ladder bank of Phoong et al. (1995), built from the symmetric, even-length 1-D ladder filter f_ladder (their β). Perfect reconstruction is structural — exact for any f_ladder. The DFB, NSDFB and the shear-based qfb_decompose all derive their filters from f_ladder (see Q2345). The pair holds a copy of f_ladder at precision T, by default float(eltype(f_ladder)), so integer taps give a Float64 pair. The constructor throws an ArgumentError for an empty, odd-length or asymmetric f_ladder; a filter that is symmetric only up to rounding is made exactly symmetric. The copy is read-only (a ReadOnlyTaps), so a pair (and the shared Q2345) cannot change after it is built.

Examples

julia> using Contourlets

julia> qfp = QuincunxFilterPair(Float32.(Q2345.f_ladder));

julia> eltype(qfp)
Float32

Directional filter banks

Contourlets.dfb_decompose — Function
dfb_decompose(bandpass, qfp::QuincunxFilterPair, l_levels; half = :both, workspace = nothing)
    -> Vector{Matrix}

Decompose bandpass into 2^l_levels directional subbands using an l_levels-deep DFB (l_levels ≥ 0; depth 0 returns a copy of bandpass).

This is the directional filter bank of Do & Vetterli (2005) built from the ladder pair qfp (normally Q2345): the subbands tile the frequency plane into 2^l_levels directional wedges. Both image dimensions must be divisible by 2^max(l_levels - 1, 1). bandpass must be indexed from 1.

half = :first or :second gives the half trees of Eslami & Radha (2006): only one of the two level-1 fans is split further, so there are 2^(l_levels-1) + 1 subbands (the split fan's wedges, which equal the corresponding subbands of the full tree, and the other fan, unsplit, on the quincunx lattice). :first splits the fan whose wedges come first in the full tree.

Examples

julia> using Contourlets, Random

julia> using Contourlets: dfb_decompose

julia> x = randn(Xoshiro(3), 32, 32);

julia> sbs = dfb_decompose(x, Q2345, 2);

julia> length(sbs), size(sbs[1])
(4, (16, 16))

References

  1. R. H. Bamberger and M. J. T. Smith, "A Filter Bank for the Directional Decomposition of Images: Theory and Design", IEEE Transactions on Signal Processing, 40(4):882–893, 1992. doi:10.1109/78.127960
  2. M. N. Do, Directional Multiresolution Image Representations, PhD thesis, EPFL, 2001, §3.2–3.3.

Contourlets.dfb_subband_sizes — Function
dfb_subband_sizes(dims, l_levels; half = :both) -> Vector{Tuple{Int,Int}}

Per-subband (rows, cols) sizes produced by an l-level DFB (l = l_levels) applied to a bandpass image of size dims = (n1, n2). With l ≥ 2 the first 2^(l-1) subbands are n1/2^(l-1) × n2/2 and the remaining 2^(l-1) are n1/2 × n2/2^(l-1); with l = 1 both are n1/2 × n2 (the quincunx lattice). A half tree (half = :first/:second) keeps the split fan's sizes and adds one n1/2 × n2 quincunx subband for the unsplit fan.

Contourlets.nsdfb_decompose — Function
nsdfb_decompose(bandpass, qfp, l_levels; tree_level = 1, half = :both)
    -> Vector{Matrix}

Nonsubsampled DFB analysis of bandpass with the ladder pair qfp and l_levels levels. Returns 2^l_levels directional subbands, each the same size as bandpass, each occupying an angular wedge of the frequency plane. Every subband commutes with circular shifts of bandpass, which must be indexed from 1.

tree_level is the pyramid split j the bandpass comes from, counted from the first, finest split (j = 1); scale s of an NSCT with scales scales has tree_level = scales + 1 - s. From j = 3 on, each directional filter Uₖ(z) is replaced by Uₖ(z^(2^m I)) with m = j − 2, so that the filters' well-resolved region covers the coarser band (da Cunha, Zhou & Do 2006, §II-A.3). Pass the same tree_level to nsdfb_reconstruct.

half selects the half trees of Eslami & Radha (2006): :first keeps splitting only the first level-1 fan and returns its 2^(l_levels-1) wedges followed by the unsplit second fan; :second returns the unsplit first fan followed by the 2^(l_levels-1) wedges of the second fan. Either gives 2^(l_levels-1) + 1 subbands, and the split fan's wedges equal the corresponding subbands of the full tree.

julia> using Contourlets, Random

julia> using Contourlets: nsdfb_decompose

julia> x = randn(Xoshiro(5), 16, 16);

julia> sbs = nsdfb_decompose(x, Q2345, 2);

julia> length(sbs), size(sbs[1]) == size(x)
(4, true)

AbstractMultiscaleTransforms.AbstractMultiscaleTransform — Type
AbstractMultiscaleTransform

Supertype of transform objects. A transform is an immutable value that holds every parameter of the decomposition (number of scales, directions per scale, filters, ...) and nothing that depends on the data's size or element type, so one transform serves arrays of any admissible size. Two transforms with equal parameters are == and have equal hash.

An implementation defines, for its transform type T:

synthesize!(x, t::T, c; workspace, threaded)synthesis into a preallocated array
similar_coefficients(t::T, x)uninitialised coefficients for data like x
subband_layout(t::T, dims)one descriptor per subband, lowpass first
subband(t::T, c, i)subband i of c, a view
OptionalDefault
analyze(t::T, x; ...)analyze!(similar_coefficients(t, x), t, x; ...)
synthesize(t::T, c; ...)synthesize! into an array of size signal_size(t, c)
signal_size(t::T, c)needed by the default synthesize, except for SubbandVector coefficients

nsubbands(t::T, dims)length(subband_layout(t, dims))
analyze(f, t::T, x; ...), synthesize!(f, x, t::T; ...) with supports_streaming(t::T) = truenot supported

Every implementation also follows these conventions; AbstractMultiscaleTransforms.Testing.test_transform checks most of them:

  • The transform holds every parameter, is immutable, and two transforms with equal parameters are == and have equal hash.
  • Every verb accepts the keywords workspace and threaded. A method that receives a workspace checks it with check_workspace before using it.
  • Wrong input throws before any work: a DimensionMismatch for a wrong size, an ArgumentError for another wrong argument, each with a message.
  • Complex data is transformed as its real and imaginary parts, so that analyze(t, x + im * y) ≈ analyze(t, x) + im * analyze(t, y) for real x and y.
  • The implementing package lists the interface's exported names in its own export, so that using it is enough.

AbstractMultiscaleTransforms.AbstractTransformWorkspace — Type
AbstractTransformWorkspace

Supertype of workspaces: everything a transform precomputes for one data size, element type and array type (filter responses, FFT plans, scratch buffers), so that repeated calls allocate little or nothing. Build one with make_workspace.

A workspace answers transform, eltype (the data element type) and size (the data size). It holds scratch buffers, so it serves one call at a time; give each task its own. A call whose transform, size or element type does not match the workspace throws (see check_workspace).

A workspace can stand in for its transform: analyze(ws, x) is analyze(transform(ws), x; workspace = ws), and likewise for the other verbs.

A transform that has plans or buffers to reuse defines its own subtype, with methods for transform, eltype and size, and make_workspace methods for make_workspace(t, T, dims) and, if the workspace depends on the array type (a GPU array, say), for make_workspace(t, x). Both accept the shared keywords listed there. A transform without one gets a DefaultWorkspace.
