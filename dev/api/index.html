API Reference

Module

Contourlets.Contourlets — Module
Contourlets

Discrete Contourlet Transform (CT) and Nonsubsampled Contourlet Transform (NSCT) implemented as a standalone Julia package.

Quick reference

FunctionDescription
ct_forward / ct_inverseDiscrete CT (nearly critically sampled)
nsct_forward / nsct_inverseNSCT (fully shift-invariant)
nsct3d_forward / nsct3d_inverse3-D NSCT on volumes, with a streaming form
surfacelet3d_forward / surfacelet3d_inverseDecimated 3-D transform, subbands at reduced resolution
ct_forward! / ct_inverse!In-place CT using a preallocated workspace
nsct_forward! / nsct_inverse!In-place NSCT
make_workspaceAllocate a reusable ContourletWorkspace
parabolic_levelsCompute optimal per-scale DFB depth array
make_nsct3d_workspaceAllocate a reusable NSCT3DWorkspace for volumes

Default filters

  • CDF97 — CDF 9/7 biorthogonal filter pair for the Laplacian Pyramid stage.
  • Q2345 — Quincunx biorthogonal filter pair for the DFB stage.

3-D

The 3-D transform is a parallel API rather than a generalisation of the 2-D one: the directional stage shares nothing with the quincunx filter bank, and is built instead from Bernstein mapping kernels (make_hourglass3d, make_nsdfb3d). See the "Theory (3-D)" page.

surfacelet3d_forward is the decimated counterpart of nsct3d_forward: the same frequency partition, but each subband is stored at its own reduced resolution (make_surfacelet3d, surfacelet3d_redundancy). It trades shift invariance for a roughly 3× smaller coefficient set.

Contourlets.nsct3d_forward — Function
nsct3d_forward(volume, params::ContourletParams3D; workspace=nothing) -> NSCT3DCoefficients

3-D Nonsubsampled Contourlet Transform. Invariant under circular shifts of the input; every subband keeps the size of volume.

See nsct3d_forward(f, volume, params) for the streaming form, which does not hold all subbands at once.

Examples

julia> using Contourlets, Random

julia> x = randn(Xoshiro(5), 16, 16, 16);

julia> p = ContourletParams3D(J = 2, L_array = [1, 2], order = 6);

julia> c = nsct3d_forward(x, p);

julia> length(c.subbands[1]), length(c.subbands[2])
(6, 12)

julia> maximum(abs, nsct3d_inverse(c, p) .- x) < 1e-10
true
source
nsct3d_forward(f, volume, params::ContourletParams3D; workspace=nothing)

Streaming 3-D NSCT: calls f(j, k, subband) for directional subband k of scale j, reusing one buffer between calls. subband is only valid until f returns — copy or reduce it there.

This is the form to use at working sizes. At 256³ Float32 with J = 3 and L = [2, 2, 3] the full coefficient set is 3.1 GB, while streaming holds two volumes plus the plans.

Returns the coarse residual.

Examples

julia> using Contourlets, Random

julia> x = randn(Xoshiro(6), 16, 16, 16);

julia> p = ContourletParams3D(J = 2, L_array = [1, 1], order = 6);

julia> total = 0.0;

julia> coarse = nsct3d_forward(x, p) do j, k, band
           global total += sum(abs2, band)
       end;

julia> total > 0 && size(coarse) == size(x)
true

Surfacelet transform (3-D, decimated)

Contourlets.SurfaceletParams3D — Type
SurfaceletParams3D

Describes a 3-D surfacelet decomposition.

  • J — number of scales. Scale j covers the frequency shell ‖ω‖_∞ ∈ [π/2^j, π/2^{j-1}], so it decimates by roughly 2^{j-1} per axis.
  • L_array — directional depth per scale, length J; scale j has 3 · 2^{L_array[j]} directional subbands.
  • poly — order of the soft-step polynomial (transition smoothness).
  • transition — width of the overlap between neighbouring wedges, as a fraction of the wedge width.
  • radial_transition — width of the overlap between neighbouring scale shells, as a fraction of the shell width.
  • angular_transition — width, in radians of |ω_i| - |ω_j|, of the overlap between neighbouring hourglasses.

Wider transitions mean smoother, better-localised surfacelets and larger support boxes; that trade-off is exactly the redundancy dial.

julia> using Contourlets

julia> SurfaceletParams3D(J = 2, L_array = [1, 2])
SurfaceletParams3D(J=2, L_array=[1, 2], …)

Surfacelet3DCoefficients{T}

source
Contourlets.Surfacelet3DPlan — Type
Surfacelet3DPlan{T}

Precomputed masks metadata and FFT plans for one volume size. Build with make_surfacelet3d.

The per-subband masks are not stored — at 256³ that would be gigabytes. Only the 1-D frequency tables, the per-scale wedge boundaries, and each subband's frequency box are kept; masks are evaluated on the fly.

The buffers and frequency tables are stored as abstract array types, so a plan built here can be moved to a device with Adapt.adapt(CuArray, plan) (the GPU extension replans the FFTs, which cannot be adapted). The support boxes are plain integers and stay shared.

source
Contourlets.make_surfacelet3d — Function
make_surfacelet3d(params::SurfaceletParams3D, dims::NTuple{3,Int}, ::Type{T}=Float64;
                 threading=Auto(), flags=FFTW.MEASURE) -> Surfacelet3DPlan

Plan the surfacelet transform for dims-sized volumes.

Planning scans every subband mask once to find its frequency support, so it costs one full-grid pass per subband. Reuse the plan.

Contourlets.ContourletCoefficients — Type
ContourletCoefficients{Td, A}

Output of ct_forward. Td is the data element type (real or complex) and A <: AbstractMatrix{Td} the storage array type — so the coefficients live wherever they were computed (a host Matrix for CPU input, a device array such as CuMatrix for a GPU input — no implicit transfer). Contains:

  • coarse: the low-pass residual after J LP stages.
  • subbands: Vector of length J; subbands[j] is a Vector of 2^L_array[j] directional subband matrices.
source
Contourlets.NSCTCoefficients — Type
NSCTCoefficients{Td, A}

Output of nsct_forward. Same structure as ContourletCoefficients (data type Td, storage type A) but each subband matrix has the same spatial size as the input image (no downsampling).

source
Contourlets.ContourletWorkspace — Type
ContourletWorkspace{Td, Tf}

Preallocated temporary buffers (data type Td, real filter precision Tf) for the Contourlet and NSCT transforms. Create with make_workspace; reuse across iterations with the mutating ! entry points.

Thread safety

A ContourletWorkspace is not thread-safe. Create a separate workspace per thread (e.g., [make_workspace(params, sz) for _ in 1:Threads.nthreads()]).

source
Contourlets.ContourletParams3D — Type
ContourletParams3D

Describes a 3-D NSCT decomposition.

  • J — number of pyramid levels.
  • L_array — directional depth per scale, length J. Scale j produces 3 * 2^(L_array[j]) directional subbands.
  • lp_filters — the pyramid filter pair (CDF97 by default).
  • order — Bernstein order of the hourglass mapping kernels; larger sharpens the boundaries between directional subbands.
  • poly — order of the 1-D halfband split polynomial.
  • transition — width of the overlap between neighbouring wedges, as a fraction of the wedge width.
  • tight — when true (the default) the directional masks are √W, making the transform a Parseval frame in the directional stage; when false they are the weights themselves and the directional inverse is a bare sum. See make_hourglass3d.
julia> using Contourlets

julia> ContourletParams3D(J = 2, L_array = [1, 2])
ContourletParams3D(J=2, L_array=[1, 2], order=12, …)
source
Contourlets.NSCT3DCoefficients — Type
NSCT3DCoefficients{Td, A}

Output of nsct3d_forward. coarse is the low-pass residual after J pyramid levels and subbands[j][k] the k-th directional subband at scale j. Every array has the spatial size of the input — the transform is nonsubsampled.

Size warning: the total coefficient volume is 1 + Σ_j 3·2^L_j copies of the input. At 256³ Float32 with J = 3 and L = [2, 2, 3] that is 3.1 GB; use the streaming form of nsct3d_forward when that does not fit.

source
Contourlets.NSCT3DWorkspace — Type
NSCT3DWorkspace{Td, T}

Reusable plans and buffers for the 3-D NSCT at one volume size and element type. Build with make_nsct3d_workspace and pass it to nsct3d_forward / nsct3d_inverse to keep repeated calls out of the allocator — the pattern iterative reconstruction algorithms need.

Directional Filter Bank (3-D)

Contourlets.HourglassFB3D — Type
HourglassFB3D{T}

Precomputed 3-D nonsubsampled hourglass filter bank for one volume size and real precision T. Build with make_hourglass3d.

Holds the two mapping-kernel frequency responses (m1 on the 3-D rfft grid, m2 on the 2-D (ω₂, ω₃) grid) rather than the three subband masks, which are derived pointwise on the fly — a third of the memory, and the polynomial evaluation is negligible next to the transforms.

source
Contourlets.make_hourglass3d — Function
make_hourglass3d(dims::NTuple{3,Int}, ::Type{T}=Float64;
                order::Int=12, poly::Int=1, tight::Bool=true,
                threading=Auto(), flags=FFTW.MEASURE) -> HourglassFB3D

Build the 3-D hourglass filter bank for dims-sized volumes.

order is the Bernstein order N of the mapping kernels: larger N sharpens the transition between hourglass subbands (Lu & Do use N = 12, which in their FIR realisation corresponds to filters of support up to 61³ — here it costs nothing but a slightly longer design step). poly is the order m of the 1-D halfband split polynomial; larger m flattens the response near the passband centres. Neither affects perfect reconstruction, which is exact for any choice.

tight selects how the three weights become filters. With tight = true (the default) the masks are √W_i, so the bank is a Parseval frame — analysis preserves energy, Σ_i ‖s_i‖² = ‖x‖² — and synthesis applies the same masks, costing one forward transform per subband plus one inverse. With tight = false the masks are the weights themselves, reconstruction is a bare sum with no transforms, and the frame-bound ratio is 3. Perfect reconstruction is exact either way.

A complex element type is accepted and produces a plan of the corresponding real precision; complex volumes are filtered as two real passes, keeping T(x + i·y) == T(x) + i·T(y) exact.

source

hourglass3d_mask(fb::HourglassFB3D, i::Int) -> Array{T,3}

The frequency-domain analysis mask of hourglass subband i (1, 2 or 3) on the rfft grid. Materialising it is only useful for inspection and tests — the transform derives mask values on the fly.

The three masks sum to 1 at every frequency when fb.tight is false, and their squares sum to 1 when it is true. See hourglass3d_weight for the underlying partition of unity in either case.

NSDFB3D{T}

3-D nonsubsampled directional filter bank: HourglassFB3D followed by a wedge refinement of each hourglass. Build with make_nsdfb3d.

source
Contourlets.make_nsdfb3d — Function
make_nsdfb3d(dims::NTuple{3,Int}, ::Type{T}=Float64;
            levels::Int=2, order::Int=12, poly::Int=1, tight::Bool=true,
            transition::Real=1.0, threading=Auto(), flags=FFTW.MEASURE)

Build a 3-D NSDFB producing 3 * 2^levels directional subbands, each the full size of the input.

levels is the total refinement depth L; it is split as evenly as possible between the two transverse planes of each hourglass (l_a = ceil(L/2), l_b = floor(L/2)), matching the balanced expansion rule of the paper. levels = 0 leaves the plain three-subband hourglass bank.

Contourlets.bernstein_table — Function
bernstein_table(N::Int, omega::AbstractVector{T}) -> Matrix{T}

Evaluate the order-N Bernstein basis at the frequencies omega, after the change of variables x = (1 - cos ω) / 2. Returns an (N+1) × length(omega) matrix whose [j+1, k] entry is binomial(N, j) x_k^j (1 - x_k)^(N-j).

The columns sum to 1, so any convex combination of rows stays in [-1, 1] when the coefficients do — this is what bounds the mapped filter responses.

Contourlets.mapping_coefficients — Function
mapping_coefficients(N::Int, d::Int, group::NTuple) -> Array{Int,d}

Coefficient tensor of the Bernstein mapping kernel whose passband is

S = {ω : max_{i ∈ group} |ω_i| ≥ max_{i ∉ group} |ω_i|},

the "simplest passband support" of Lu & Do (2008), Proposition 1 — the optimal choice for splitting a node of the hourglass cascade tree.

Entries are +1 inside S, -1 outside, and 0 on the boundary, evaluated at the Bernstein sample points j / N. Only the ordering of the indices matters, which is why the sample points never have to be converted back to frequencies.

Contourlets.mapping_response — Function
mapping_response(coeffs, tables) -> Array

Evaluate a multivariate Bernstein mapping kernel on a DFT grid. coeffs is the (N+1)^d coefficient tensor from mapping_coefficients and tables is a d-tuple of per-axis Bernstein tables from bernstein_table, one per grid axis. The result is the real, zero-phase frequency response M(ω) on the product grid, with |M| ≤ 1 wherever the coefficients are in [-1, 1].

Evaluated by successive axis contractions rather than by summing (N+1)^d separable outer products, so the cost is O(N · ∏ nᵢ) and not O(N^d · ∏ nᵢ).

Contourlets.halfband_split — Function
halfband_split(x, m::Int) -> f₀

The maximally flat 1-D polynomial used to turn a mapping kernel into a two-channel split:

f₀(x) = ((1+x)/2)^(m+1) · Σ_{k=0}^{m} binomial(m+k, k) · ((1-x)/2)^k,
f₁(x) = 1 - f₀(x).

f₀(1) = 1, f₀(-1) = 0, and f₀(x) + f₀(-x) = 1, so f₁(x) = f₀(-x) — the two channels are mirror images and their sum is exactly 1. With synthesis polynomials g₀ = g₁ = 1 the Bézout/perfect-reconstruction condition f₀g₀ + f₁g₁ = 1 therefore holds identically, and reconstruction is a plain sum of the subbands.

m controls the transition sharpness: m = 0 gives (1+x)/2, larger m is flatter at x = ±1 at the cost of a steeper polynomial.
